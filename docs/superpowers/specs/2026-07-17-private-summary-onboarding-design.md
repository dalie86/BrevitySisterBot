# BrevitySisterBot 0.2.0 — личные сводки без группового ритуала

Дата: 2026-07-17  
Статус: согласовано

## 1. Проблема

Текущая версия требует, чтобы пользователь хотя бы один раз отправил
`/summary` внутри группы. Только после этого бот связывает пользователя с
группой и разрешает получать её сводки в личном чате.

Это внутренняя техническая связь, которая не должна становиться пользовательским
ритуалом. Пользователь должен иметь возможность впервые обратиться к боту
лично, выбрать доступную группу и сразу получить сводку.

## 2. Принятое решение

Используется гибрид из трёх способов обнаружения группы:

1. кнопка «Получить сводку лично» в сообщении, которое бот публикует после
   `/enable_daily`;
2. нативный Telegram-выбор группы в личном чате через
   `KeyboardButtonRequestChat`;
3. пассивное обнаружение по обычным сообщениям пользователя в подключённой
   группе и существующему групповому `/summary`.

После первого успешного обнаружения бот запоминает связь пользователя с
группой. Перед каждой личной выдачей членство проверяется заново.

BrevitySisterBot должен быть администратором каждой подключённой группы. Это
нужно для гарантированной работы `getChatMember` для других пользователей и
получения событий `chat_member`.

## 3. Подключение группы

Администратор группы добавляет BrevitySisterBot и выдаёт ему права
администратора. После команды `/enable_daily` бот проверяет:

- инициатор команды является администратором группы;
- сам бот является администратором группы.

Если обе проверки успешны, группа включается и бот публикует обычное сообщение
с предложением получать сводки лично. Сообщение не закрепляется автоматически.
При необходимости администратор закрепляет его средствами Telegram.

Сообщение содержит inline-кнопку:

```text
Получить сводку лично
```

Кнопка ведёт по deep link:

```text
https://t.me/{{TELEGRAM_BOT_USERNAME}}?start=summary_{{GROUP_LINK_TOKEN}}
```

Повторная обработка одного Telegram update не создаёт дубликат сообщения за
счёт существующего durable effect ledger.

## 4. Переход из группы в личный чат

Для каждой группы создаётся случайный постоянный токен длиной не менее 128 бит.
Токен не содержит `chat_id` и не является авторизацией — это только указатель
на группу.

После нажатия кнопки:

1. Telegram открывает личный чат с ботом;
2. при первом обращении Telegram может потребовать стандартное нажатие Start;
3. бот получает `/start summary_{{GROUP_LINK_TOKEN}}`;
4. разрешает токен в `chat_id`;
5. проверяет, что группа известна BrevitySisterBot;
6. проверяет, что сам бот остаётся администратором;
7. проверяет текущее членство пользователя через `getChatMember`;
8. сохраняет связь пользователя с группой;
9. сразу запускает сегодняшнюю личную сводку без дополнительного подтверждения.

Пересланная постороннему ссылка не даёт доступа: проверка членства обязательна.

## 5. Прямой `/summary` в личном чате

Перед показом известных групп бот повторно проверяет доступ к каждой из них.

### Одна доступная группа

Бот сразу принимает запрос и готовит сводку.

### Несколько доступных групп

Бот показывает существующий список inline-кнопок с названиями доступных групп.
Кнопки содержат непрозрачные одночасовые selection tokens, а не `chat_id`.

### Нет доступных групп

Бот показывает reply-кнопку Telegram:

```text
Выбрать группу
```

Кнопка использует `request_chat` со следующими критериями:

- `chat_is_channel = false`;
- `bot_is_member = true`;
- `request_title = true`.

Telegram возвращает `Message.chat_shared`. Бот извлекает `chat_id`, затем
проверяет, что:

- `request_id` существует, принадлежит этому пользователю, не истёк и ещё не
  был использован;
- группа уже существует в `tracked_chats`;
- BrevitySisterBot является её администратором;
- пользователь является текущим участником.

После успешной проверки связь запоминается, reply-клавиатура убирается и сразу
запускается сегодняшняя личная сводка.

## 6. Пассивное обнаружение и события состава

Обычное сообщение пользователя в подключённой группе является достаточным
свидетельством для добавления группы в его личный список. Пользователь не
должен отправлять специальную команду.

Webhook дополнительно принимает `chat_member`. Полный реестр всех участников
не строится. События используются для известных записей:

- `creator`, `administrator`, `member` и активный `restricted` сохраняют
  доступ;
- `left`, `kicked` и неактивный `restricted` отключают личный доступ.

Даже при наличии события перед фактической выдачей выполняется свежий
`getChatMember`.

## 7. Семантика `/disable_daily`

`/disable_daily` выключает только автоматическую публикацию в 21:00.

- ручные групповые сводки продолжают работать;
- личные сводки продолжают работать;
- опубликованное сообщение с кнопкой остаётся действительным;
- токен группы не отзывается.

## 8. Данные и миграция

Существующая миграция `001_initial.sql` не изменяется. Создаётся
`002_private_summary_onboarding.sql`.

Минимальные изменения схемы:

- `tracked_chats.private_link_token CHAR(32) NOT NULL` после backfill
  существующих групп;
- уникальный индекс по `private_link_token`;
- `chat_share_requests` с `request_id`, `user_id`, временем истечения и
  временем использования;
- при необходимости поля последнего onboarding-сообщения могут быть добавлены
  позднее, но в текущий объём не входят.

Существующее `chat_members.summary_linked_at` означает, что группа доступна
пользователю в личном интерфейсе. Оно устанавливается при:

- переходе по deep link;
- успешном `chat_shared`;
- обычном сообщении пользователя в подключённой группе;
- групповом `/summary`.

Имя бота задаётся обязательной переменной окружения
`TELEGRAM_BOT_USERNAME` без символа `@`.

Миграция заполняет токены уже существующих групп через UUID без дефисов, затем
делает поле обязательным. Для новых групп токен создаётся криптографически
стойким генератором приложения.

Числовой Telegram ID самого бота извлекается из префикса
`TELEGRAM_BOT_TOKEN`; отдельная переменная окружения для него не нужна.

## 9. Изменения Telegram boundary

Parser должен поддержать:

- `/start` с deep-link payload в личном сообщении;
- `Message.chat_shared`;
- `Update.chat_member`.

Telegram client/gateway должен поддержать:

- проверку статуса самого бота в группе;
- reply markup с `request_chat`;
- удаление reply-клавиатуры после выбора.

Для каждого показа нативного picker создаётся случайный signed 32-bit
`request_id`, привязанный к пользователю на один час. Успешный `chat_shared`
помечает запрос использованным, поэтому старое или повторное событие не может
переключить группу.

`setWebhook` должен явно добавить `chat_member` в `allowed_updates`.

## 10. Ошибки и пользовательское поведение

- Бот не администратор: `/enable_daily` отклоняется до изменения настроек.
- Неизвестный токен: предлагается нативный выбор группы.
- Пользователь не состоит в группе: доступ не сохраняется, сводка не выдаётся.
- Выбранная группа не подключена: пользователю сообщается, что администратор
  должен выполнить `/enable_daily`.
- Часть запомненных групп недоступна: они исключаются из выбора.
- Все запомненные группы недоступны: показывается нативный выбор группы.
- Менее пяти сообщений: связь сохраняется, пользователь получает существующее
  уведомление о пороге.
- Ошибка проверки Telegram: доступ не выдаётся оптимистично; update переходит
  в существующий recovery-процесс.

## 11. Тестирование

### Unit

- parsing deep-link payload;
- parsing `chat_shared`;
- parsing `chat_member` и статусов restricted/left/kicked;
- генерация и разрешение непрозрачного group token;
- фильтрация запомненных групп после повторной проверки;
- формирование `request_chat` reply markup.

### Contract

- payload группового deep link;
- Telegram `getChatMember` для пользователя и самого бота;
- `setWebhook.allowed_updates` содержит `chat_member`;
- reply keyboard соответствует Bot API.

### E2E

- `/enable_daily` при боте-администраторе публикует onboarding-сообщение;
- бот без прав администратора не подключает группу;
- deep link связывает пользователя и сразу запускает личную сводку;
- пересланный токен не обходит проверку членства;
- прямой `/summary` без групп показывает нативный picker;
- `chat_shared` для подключённой группы связывает и запускает сводку;
- одна запомненная группа запускается автоматически;
- несколько групп показывают безопасный выбор;
- выход из группы исключает её из личного доступа;
- `/disable_daily` не отключает личные сводки;
- повторная обработка update не дублирует onboarding или личную сводку.

## 12. Вординг и единый источник текстов

`content/bot_copy.ru.toml` становится единственным runtime-источником
пользовательских текстов, кнопок, шаблонов сводки и LLM-промптов. Python-код не
должен содержать дублирующиеся пользовательские формулировки.

Файл использует стабильные английские ключи и собственные именованные
переменные вида `{{variable}}`. Такой синтаксис не конфликтует с JSON внутри
LLM-промптов. При загрузке приложение проверяет:

- TOML синтаксически корректен;
- присутствуют все обязательные секции и ключи;
- для каждого ключа используется только разрешённый набор переменных;
- обязательные переменные не удалены;
- ограничения Telegram соблюдены для подписей кнопок и итоговой сводки.

Основной и резервный шаблоны содержат постоянный жирный заголовок
`📝 Краткая сводка за сегодня`. Сообщения со сводкой отправляются с Telegram
`parse_mode=HTML`. Все динамические значения — результат модели, названия тем,
детали, имена участников и фрагменты сообщений — проходят HTML-экранирование
до подстановки. HTML из TOML считается доверенной частью шаблона; HTML из
динамических данных никогда не интерпретируется Telegram.

Ошибка конфигурации должна останавливать запуск процесса с понятной записью в
логе, а не проявляться во время обработки пользовательского запроса. Файл
загружается один раз при старте процесса; применить редакторские изменения
можно штатным перезапуском приложения. Секретов и переменных окружения в TOML
нет. Каталог `content/` включается в пакет и сценарий деплоя.

`docs/BOT_COPY_RU.md` является расширенным редакторским представлением с
контекстом показа каждого сообщения. После подключения TOML он генерируется
скриптом из единого источника и не редактируется вручную. CI проверяет, что
сгенерированный Markdown не расходится с TOML.

Подготовленный TOML и copy-deck сохраняют следующие изменения:

- удаляется требование предварительного группового `/summary`;
- добавляется onboarding-сообщение группы и подпись кнопки;
- добавляется нативный выбор группы;
- добавляются сообщения о правах бота, неизвестной ссылке и неподключённой
  группе;
- описание личного сценария приводится в соответствие с новой механикой.

Точный финальный текст остаётся предметом отдельной UX-редактуры и не меняет
описанную архитектуру.

## 13. Вне объёма

- автоматическое закрепление onboarding-сообщения;
- Mini App;
- полный каталог участников группы;
- автоматическая рассылка сводки в личные чаты без запроса пользователя;
- изменение команд `/enable_daily`, `/disable_daily` и `/summary`;
- отзыв токена при `/disable_daily`.
