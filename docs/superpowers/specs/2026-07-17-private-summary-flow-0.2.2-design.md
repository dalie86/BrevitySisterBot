# BrevitySisterBot 0.2.2 — личный `/summary`

## Цель

Убрать ошибочный автоматический выбор одной группы, сделать `/start` и
`/summary` разными действиями и отправлять подтверждение запроса до медленных
проверок Telegram и генерации сводки.

## Подтверждённые причины

- `linked_groups()` возвращает только группы с `summary_linked_at`, но
  `/enable_daily` не запоминает подключившего группу администратора. Поэтому
  подключённая позднее группа может отсутствовать в личном выборе.
- Обработчик проверяет членство бота и пользователя через Telegram API до
  первого видимого ответа. На production это добавило 4,53 секунды.
- Подтверждение уже вызывается до `generate()`, но после проверок доступа.
  При готовом кеше подтверждение и сводка отправляются почти одновременно.
- Обычный `/start` не имеет собственного ответа, а deep-link
  `/start summary_<token>` сразу запускает сводку конкретной группы.

## Рассмотренные варианты

1. **Рекомендуемый: безопасный выбор с накопленной памятью.** Бот использует
   известные привязки, но при наличии других подключённых групп не делает вид,
   что единственная известная группа — единственно доступная. В сомнительном
   случае он открывает нативный Telegram-выбор, а выбранную группу запоминает.
   Это не раскрывает названия чужих групп и не требует серии внешних запросов.
2. Проверять членство пользователя во всех подключённых группах через
   `getChatMember`. Это даёт inline-список сразу, но до 20 групп означает много
   сетевых запросов, медленный первый ответ и лишнюю нагрузку на shared hosting.
3. Всегда открывать нативный Telegram-выбор. Это наиболее просто и безопасно,
   но заставляет выбирать группу даже тогда, когда бот достоверно знает, что
   она одна.

Фиксируется вариант 1. Искусственная задержка между подтверждением и готовой
сводкой не используется: она ухудшает отклик и удерживает webhook без пользы.

## Пользовательские сценарии

### Обычный `/start`

Бот отправляет короткое приветствие и inline-кнопку «Получить сводку».
Генерация не запускается. Нажатие кнопки запускает тот же сценарий выбора, что
и личная команда `/summary`.

### Deep-link из группы

`/start summary_<token>` остаётся явным запросом сводки для конкретной группы:
бот отправляет подтверждение, проверяет доступ и запускает генерацию. Это
сохраняет смысл групповой кнопки «Получить сводку лично».

### Личный `/summary` и кнопка из `/start`

1. Бот читает известные пользователю группы и число подключённых групп.
2. Если известных групп две или больше, бот сразу показывает inline-кнопки с
   их названиями. Актуальный доступ проверяется только после выбора.
3. Если известна одна группа и всего подключена одна группа, она выбирается
   автоматически.
4. Если известна одна группа, но подключённых групп больше, бот открывает
   нативный Telegram-выбор: другие доступные группы могли ещё не попасть в БД.
5. Если известных групп нет, бот также открывает нативный Telegram-выбор.
6. После успешного выбора группа запоминается. При двух известных группах
   следующие запросы получают обычные inline-кнопки.

Нативный выбор должен требовать, чтобы бот состоял в выбранной группе. После
выбора сервер дополнительно проверяет, что группа подключена, бот является её
администратором, а пользователь остаётся участником.

### Подключение новой группы

После успешного `/enable_daily` вызывавший команду администратор сразу
запоминается как связанный с этой группой. Отдельная команда `/summary` внутри
группы для привязки не нужна.

## Порядок сообщений и производительность

- Пока группа ещё не определена, первым ответом является выбор группы; текст
  «до 2 минут» не отправляется преждевременно.
- Как только группа определена, бот немедленно отправляет
  `summary_accepted` — до `getChatMember` и до обращения к модели.
- Затем бот проверяет доступ. При отказе подтверждение сменяется точным
  сообщением об ошибке; сводка не генерируется.
- При успешной проверке генерация запускается в рамках того же webhook-запроса,
  то есть без ожидания пятиминутной recovery-джобы.
- Если сводка уже есть в кеше, она может прийти сразу после подтверждения.
  Специальная пауза не добавляется.
- Callback Telegram подтверждается через `answerCallbackQuery` до остальных
  операций, чтобы кнопка не оставалась в состоянии загрузки.

## Архитектурные изменения

- `ChatRepository` получает дешёвый запрос количества включённых групп.
- `MySqlChatRepository` реализует его через `COUNT(*) WHERE enabled = 1`.
- `OnDemandSummaryHandler` разделяет начало личного сценария, выбор группы,
  раннее подтверждение и последующую проверку доступа.
- `OnDemandSummaryService` не должен повторно отправлять подтверждение, если
  обработчик уже сделал это. Групповой `/summary` сохраняет одно подтверждение.
- `GroupUpdateHandler` запоминает администратора после успешного
  `/enable_daily`.
- Все новые пользовательские тексты остаются в
  `content/bot_copy.ru.toml`, который продолжает быть единственным источником
  правды.
- Существующая durable-idempotency Telegram effects сохраняется: повторная
  доставка update не дублирует ни раннее подтверждение, ни результат.

Схема БД не меняется. Существующая пропущенная привязка восстанавливается,
когда пользователь выбирает вторую группу через нативный Telegram-выбор.

## Ошибки и восстановление

- Ошибка Telegram API после раннего подтверждения переводит update в retry;
  уже отправленное подтверждение повторно не отправляется.
- Недоступная или отключённая выбранная группа получает существующее точное
  сообщение без запуска модели.
- Если тот же набор сообщений уже готовится, используется существующий текст
  `summary_in_progress`.
- Recovery каждые пять минут остаётся страховкой для оборванных webhook, но не
  штатным способом запуска личной сводки.

## Тестирование и релиз

Реализация выполняется через RED–GREEN TDD. Обязательные регрессии:

- `/enable_daily` сразу запоминает администратора группы;
- обычный `/start` показывает приветствие и кнопку, но не генерирует сводку;
- кнопка `/start` и `/summary` входят в один сценарий выбора;
- одна известная группа при нескольких подключённых не выбирается молча;
- две известные группы показываются без предварительных Telegram API-проверок;
- подтверждение отправляется до первой проверки членства и до генерации;
- deep-link сохраняет прямой запрос конкретной группы;
- retries не дублируют Telegram effects;
- полный набор unit, integration, e2e, Ruff, compileall, copy-render и
  `git diff --check` проходит.

Релиз: `0.2.2`. После независимого code review он разворачивается на Beget,
проверяется живым сценарием и пушится в GitHub.
